# 아키텍처 결정 기록 (ADR)

| 문서 버전 | v1.0 (M0에서 확정) | 갱신일 | 2026-07-08 |
|---|---|---|---|

각 결정의 상세 배경은 [ROADMAP.md](ROADMAP.md) 3장 참조. 상태: ✅ 채택 / 🔄 재평가 예정.

## ADR-001 — 전술 보드 스키마 v2: 선수 id 도입 ✅

- **맥락**: v1.1 애니메이션(프레임 간 선수 대응), v1.2 편집기(선수 추가/삭제), v1.1.5 3D 뷰어가 모두 "선수를 식별"해야 한다. 인덱스 기반 대응은 편집기의 추가/삭제에서 파산한다.
- **결정**: `PlayerPos.id`(보드 내 유일, 필수), `Arrow.subjectId`(행위 주체, optional) 도입. 마이그레이션은 `scripts/migrate-board-ids.ts`로만 수행(수기 금지). **한 번 배포된 id는 변경하지 않는다.**
- **id 규칙**: role 소문자 슬러그, 동일 role 복수 시 1부터 접미사(`cb1`, `cb2`). 상대 팀은 `o-` 접두사.
- **결과**: 20종 전체 마이그레이션 완료, 화살표 83/85 subjectId 자동 매핑, 렌더 회귀 0건(스냅샷 검증).

## ADR-002 — 애니메이션 데이터 구조: Board.steps (additive) ✅

- **결정**: v1.1에서 `Board`에 optional `steps` 배열(단계별 위치·화살표·캡션, 선수 id 기반)을 추가한다. 기존 단일 스냅샷 보드는 "1단계 시퀀스"로 해석 — 기존 데이터 재마이그레이션 불필요. 커스텀 보드(v1.2)·3D 뷰어(v1.1.5)도 동일 스키마 재사용. 명칭은 `steps`로 통일(boardSequence 등 별칭 금지).
- **구현 시점**: 타입·설계는 v1.1 착수 시 동결, 콘텐츠 팩 제작 중 스키마 변경 금지.

## ADR-003 — 호스팅: Cloudflare Pages ✅

- **결정**: 정적 호스팅은 Cloudflare Pages. 근거: 무료 티어 무제한 대역폭 + **PR마다 프리뷰 URL 자동 생성**(PM이 코드를 읽지 않고 눈으로 검증하는 루프의 핵심). 해시 라우팅이라 SPA rewrite 불필요.
- **절차**: [DEPLOY.md](DEPLOY.md).

## ADR-004 — 라우팅: 해시 라우팅 유지 (v1.2까지) ✅ 🔄

- **결정**: History API 전환은 PWA 캐시·필터 직렬화·기존 딥링크와 상호 회귀 위험이 커서 보류. 검색 유입 실측 데이터 확보 후(v1.2 이후) 재평가.

## ADR-005 — 공유 미리보기: 대표 OG 이미지 1장 ✅

- **결정**: 정적 호스팅 + 해시 라우팅 = 전술별 OG 원천 불가(단일 index.html). 대표 OG 1장으로 타협하고, 전술별 공유는 v1.2 이미지 내보내기로 해소.

## ADR-006 — 애널리틱스: 쿠키리스 경량 계측 ✅

- **결정**: 쿠키리스 도구(Plausible/GoatCounter 계열) 또는 자체 수집 엔드포인트. 클라이언트는 `src/lib/analytics.ts`의 `track()` 래퍼로 통일 — `VITE_ANALYTICS_URL` 미설정 시 no-op이며, 계측 실패·차단이 앱 동작에 영향을 주지 않는다(M0 게이트). 이벤트 정의는 [EVENTS.md](EVENTS.md) 단일 문서로 관리.

## ADR-007 — v1.3 백엔드: Supabase (BaaS) ✅ (v1.3 착수 시 재확인)

- **결정**: 무개발자 2인 팀에서 자체 서버는 운영 부채 — Supabase 채택. 조건: RLS 정책 테스트(허용+거부 각 1건 이상)를 CI에 강제. 데이터 접근은 모듈 1개로 모으는 얇은 추상화까지만(과설계 금지).

## ADR-008 — 3D 렌더링 스택: three.js (클래식 WebGLRenderer) ✅ (스파이크 실측으로 개정)

- **맥락**: "피파 전술 화면" 룩의 3D 보기 요구. 당초 WebGPURenderer+WebGL2 폴백을 선택했으나, v1.1-E4 스파이크 실측(docs/SPIKE-3D.md)에서 **클래식 WebGLRenderer가 청크 37% 작고(216→136KB gzip) 폴백 경로 fps가 3배 이상**(소프트웨어 렌더링 19→61fps)으로 나왔다. 캡슐 수준의 씬에서 WebGPU의 이점이 없다.
- **결정(개정)**: three.js **클래식 WebGLRenderer** 채택. WebGPU 전환은 캐릭터 모델 등 무거운 씬이 들어오는 시점에 재평가(전환 비용은 렌더러 생성부 교체 수준 — 보간·씬 코드는 무관). **옵션 모드 · 뷰어 전용 · lazy-load** 원칙 유지 — 기본 번들 불변(gzip 90KB 게이트), 편집은 2D 유지. 게임엔진 WASM export(20~50MB)·네이티브 앱 기각.
- **에셋 정책**: CC0(Quaternius 등) + Mixamo만 사용. **상용 게임 립(rip) 에셋은 CC 표기가 있어도 무효 — 절대 금지.** 실존 구단 유니폼·엠블럼·선수 얼굴 재현 금지(상표권·초상권).
- **검증**: v1.1 말 스파이크에서 중저가 안드로이드 실기기 30fps + 청크 예산 실측 → v1.1.5 착수 게이트.
