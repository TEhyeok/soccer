## 구현 범위 (PoC)

- `#/t/:id/3d` 라우트 + 상세 페이지 "3D 보기 (베타)" 진입점
- three.js **WebGPURenderer + WebGL2 자동 폴백** (ADR-008 스택 그대로)
- 피치(캔버스 텍스처 라인) + 선수 22명 **InstancedMesh**(팀당 draw call 1) + 공
- 카메라 프리셋 3종(방송/탑다운/골대 뒤) + OrbitControls 자유 회전
- **steps 시퀀스 3D 재생 — 2D와 동일한 `lib/playback` 순수 함수 재사용** (렌더러 독립 설계 실증)
- pixelRatio 상한 1.5, 실시간 그림자 없음, React.lazy 별도 청크

미포함(v1.1.5 본 구현으로 이월): CC0 캐릭터 모델(Quaternius)·애니메이션, 품질 자동 티어, 3D 미지원 E2E.
현재 선수는 캡슐 지오메트리 플레이스홀더.

| 항목 | WebGPURenderer (three/webgpu) | **클래식 WebGLRenderer (채택)** |
|---|---|---|
| 3D 청크 (gzip) | 216.4KB | **136.0KB (−37%)** |
| 소프트웨어 렌더링 fps (GPU 없는 컨테이너, 최악 하한) | 19 | **61 (3.2배)** |
| 동작 | 정상 (WebGL2 폴백 경유) | 정상 |

결론: 캡슐 수준의 씬에서 WebGPU의 성능 이점은 없고 무게(TSL 노드 시스템)만 부담이다.
**베타는 클래식 WebGLRenderer로 확정 (ADR-008 개정)**. 캐릭터 모델·고급 셰이딩이 들어오는
시점에 WebGPU 재평가 — 렌더러 생성부만 교체하면 되도록 씬 코드는 렌더러 중립으로 유지했다.

## 판단 재료

1. **아키텍처는 통과.** 선수 id 기반 steps(ADR-001/002)와 보간 함수 공유 덕분에 3D 뷰어가
   데이터·로직 수정 0줄로 성립했다. lazy 분리로 기본 경험(번들 게이트) 무손상.
2. **청크 216KB는 논의 필요.** `three/webgpu`(TSL 노드 시스템 포함)가 무겁다. 대안:
   - (a) 그대로 — 옵션 모드이므로 첫 클릭 시 1회 다운로드로 수용
   - (b) 클래식 `WebGLRenderer`로 전환 시 청크 대폭 감소 예상 — WebGPU 이점 포기
   - v1.1.5 착수 시 (a)/(b)를 실측 비교해 결정 (게이트: 지연 청크 예산 합의)
3. **SW 프리캐시가 3D 청크를 포함**하게 됨(설치 시 216KB 추가 다운로드).
   v1.1.5에서 프리캐시 제외(런타임 캐시로만) 여부 결정 필요.
4. **FPS 19는 GPU가 전혀 없는 컨테이너의 소프트웨어 렌더링 수치** — 실기기 하한 참고용.
   GPU 있는 실제 폰에서는 훨씬 높을 것으로 예상되나, **게이트 항목인 "중저가 안드로이드
   실기기 30fps"는 PM 실기기 확인이 필요**하다 (프리뷰 URL 또는 시뮬레이터 아티팩트 불가 —
   3D는 lazy 청크라 배포 환경에서 확인).
