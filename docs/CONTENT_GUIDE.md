# 콘텐츠 스타일 가이드 — 전술 항목 품질 기준

| 문서 버전 | v1.0 (M0) | 갱신일 | 2026-07-08 |
|---|---|---|---|

"콘텐츠가 곧 제품"(로드맵 원칙 4). 모든 전술 항목은 이 기준을 통과해야 병합된다.
형식 규칙은 `src/data/validate.ts`가 자동 검증하고(CI), 내용 품질은 이 문서의 체크리스트로 사람이 검수한다.

## 1. 항목 필수 구성

| 필드 | 기준 |
|---|---|
| `name` / `nameEn` | 한국어 통용 명칭 + 영문 병기. 두문자어보다 풀네임 우선 |
| `summary` | 1문장. "무엇을 + 어떻게 + 왜"가 들어간 한 줄 정의 |
| `description` | 2~3문단. ① 정의와 구조 ② 작동 원리(왜 통하는가) ③ 요구 조건·한계. 문단당 2~4문장 |
| `strengths` / `weaknesses` | 각 3~4개. 대칭적 나열보다 실전에서 체감되는 순서로 |
| `keyPoints` | 3~5개. **훈련장에서 코치가 말하듯** 실행 가능한 지시문으로 (숫자·거리·시간 포함 권장) |
| `counters` | 이 전술을 **상대하는** 전술의 id. 실존 id만(CI 검증). 세트피스는 카운터 개념이 성립하지 않으므로 빈 배열 허용 |
| `famousTeams` | 2~3개. "팀 (감독)" 형식. 확실한 사례만 — 불확실하면 빼는 쪽을 택한다 |
| `tags` | 2~4개. 검색을 위한 것 — 사용자가 칠 법한 단어로 |

## 2. 전술 보드 규칙

- **좌표계**: x 0~100(좌→우), y 0~100(자기 골문→상대 골문). 좌표는 정수 권장.
- **선수 id (ADR-001)**: role 소문자 슬러그 + 동일 role 복수 시 접미사(`cb1`, `cb2`). 상대는 `o-` 접두사. **배포된 id는 절대 변경 금지** (즐겨찾기·steps가 참조).
- **role 표기**:
  - 일반 전술: 포지션 축약(GK, LB, CB, RB, WB, DM, CM, AM, LM, RM, LW, RW, ST)
  - 세트피스 우리 팀: K(키커), K1/K2(복수 키커), S(숏 옵션), W(벽 옆 방해), A~E(침투 주자), R(잔류/리바운드)
  - 세트피스 상대 팀: 맥락상 라벨이 불필요하면 `''`(익명 도트) 허용. 골키퍼는 GK 표기
- **화살표**: run(이동, 실선) / pass(패스, 점선) / press(압박, 적색). `subjectId`는 행위 주체 선수 id — 새 항목은 가급적 부여.
- **밀도 상한**: 보드당 화살표 6개 이하. 한 보드는 한 장면만 — 두 장면이 필요하면 v1.1 steps로.

## 3. 내용 품질 체크리스트 (검수자용)

- [ ] summary만 읽고도 전술이 뭔지 알 수 있는가
- [ ] description에 "왜 통하는가"(원리)가 있는가 — 백과사전식 나열 금지
- [ ] keyPoints가 실행 가능한가 (예: "간격 유지" ✕ → "두 줄 간격 15m 이내" ○)
- [ ] counters가 논리적으로 성립하는가 (이 전술의 약점을 찌르는 전술인가)
- [ ] 고유명사(감독·팀·시즌) 사실 확인 — 불확실하면 삭제
- [ ] 보드가 description의 핵심 장면과 일치하는가
- [ ] `npm test` 통과 (형식·참조 무결성 자동 검증)

## 4. 제작 파이프라인 (PM + AI 페어)

1. PM이 전술 선정 (로드맵 콘텐츠 팩 목록 기준)
2. AI가 초안 작성 (이 가이드 준수) → 데이터 파일에 추가 — **코드 수정 0줄이어야 정상**
3. `npm test`로 형식 검증 → PR 생성 → 프리뷰 URL에서 보드 눈 검수
4. PM이 3장 체크리스트로 내용 검수 (고유명사 전수 확인)
5. 병합 → 스냅샷 기준선 갱신(`vitest -u`) 포함

## 5. 금지 사항

- 상용 게임·중계 화면 캡처, 립 에셋 사용 (ADR-008)
- 실존 선수 얼굴·초상 묘사, 구단 엠블럼·유니폼 재현
- 출처 불명의 통계 인용 (기대득점 수치 등은 "~로 평가된다" 수준으로)
