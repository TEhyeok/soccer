# PRD — 택틱북 (TacticBook): 축구 전략·전술 모음집

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-07-08 |
| 상태 | MVP 개발 승인 |

## 1. 제품 개요

**택틱북**은 축구 포메이션과 전략·전술을 한곳에 모아, 인터랙티브 전술 보드로
시각화해 보여주는 전술 학습 앱이다. 아마추어 선수, 유소년/동호회 지도자,
전술에 관심 많은 팬이 "이 전술이 뭐고, 언제 쓰고, 어떻게 깨는지"를
5분 안에 이해할 수 있게 하는 것이 목표다.

### 문제 정의
- 축구 전술 정보는 유튜브 영상, 블로그, 커뮤니티에 파편화되어 있고 깊이가 제각각이다.
- 텍스트만으로는 선수 배치와 움직임을 직관적으로 이해하기 어렵다.
- 동호회 감독/주장이 경기 전에 "우리 오늘 이렇게 하자"라고 보여줄 만한 간단한 도구가 없다.

### 타깃 사용자 (페르소나)
1. **동호회 주장 민준(32)** — 주말 리그 전 팀 단톡에 전술 공유. 포메이션별 장단점과 상대 전술 카운터를 빠르게 찾고 싶다.
2. **유소년 코치 서연(28)** — 훈련 세션에서 압박 트리거, 세트피스 루틴을 아이들에게 그림으로 설명하고 싶다.
3. **전술 덕후 팬 지호(24)** — 경기 보다가 "저게 게겐프레싱인가?" 궁금할 때 바로 찾아보고 싶다.

## 2. 목표와 성공 지표

| 목표 | 지표 (North Star 후보) |
|---|---|
| 전술 이해를 빠르게 | 상세 페이지 평균 체류 90초 이상 |
| 재방문하는 레퍼런스가 되기 | 주간 재방문율 25% 이상, 즐겨찾기 사용률 30% |
| 콘텐츠 신뢰도 | 전술 항목당 이탈률 40% 이하 |

MVP 단계에서는 계측 없이 출시하고, v1.1에서 경량 애널리틱스를 붙인다.

## 3. MVP 범위 (v1.0 — 이번 릴리스)

### 포함 (In)
- **전술 라이브러리**: 5개 카테고리 20개 항목
  - 포메이션 7종: 4-3-3, 4-4-2, 4-2-3-1, 3-5-2, 3-4-3, 5-3-2, 4-4-2 다이아몬드
  - 공격 전술 4종: 티키타카, 역습, 측면 공격, 롱볼 다이렉트
  - 수비 전술 3종: 로우 블록, 미드 블록, 오프사이드 트랩 & 하이라인
  - 압박·전환 3종: 게겐프레싱, 하이 프레스, 압박 트리거 & 커버 섀도
  - 세트피스 3종: 니어포스트 코너, 직접 프리킥 루틴, 숏 코너
- **인터랙티브 전술 보드**: SVG 축구장 위 선수 배치 + 움직임(런/패스/압박) 화살표, 카드용 미니 보드
- **탐색**: 카테고리 칩 필터, 난이도 필터, 텍스트 검색(이름/태그/요약)
- **상세 페이지**: 개요, 작동 원리, 강점/약점, 핵심 포인트, 카운터 전술, 대표 팀, 연관 전술
- **즐겨찾기**: localStorage 기반, 즐겨찾기만 보기 필터
- **모바일 우선 반응형** + 딥링크 가능한 해시 라우팅 (`#/t/f433`)

### 제외 (Out — 백로그로)
- 사용자 계정/로그인, 서버 백엔드 (MVP는 정적 데이터)
- 사용자가 직접 그리는 커스텀 전술 보드 (v1.2)
- 애니메이션 재생(움직임 시퀀스) (v1.1)
- 다국어(영어) 지원, 커뮤니티/댓글, 영상 링크 큐레이션

## 4. 사용자 스토리 (MVP)

1. 사용자는 홈에서 전체 전술을 카드로 훑어보고 카테고리로 거를 수 있다.
2. 사용자는 "게겐프레싱"을 검색해 3탭 이내에 상세 화면에 도달할 수 있다.
3. 사용자는 상세 화면에서 선수 배치와 움직임 화살표를 보고 전술의 작동 방식을 이해할 수 있다.
4. 사용자는 특정 전술의 카운터(상성) 전술로 바로 이동할 수 있다.
5. 사용자는 자주 보는 전술을 즐겨찾기하고 모아볼 수 있다.

## 5. 기술 결정

| 결정 | 선택 | 근거 |
|---|---|---|
| 플랫폼 | 반응형 웹앱 (SPA) | 스토어 심사 없이 즉시 배포·검증. 추후 PWA → 네이티브 래핑 경로 확보 |
| 스택 | React 18 + Vite + TypeScript | 생태계 표준, 빠른 빌드, 타입 안정성 |
| 라우팅 | 자체 해시 라우터 | MVP에 라이브러리 불필요, 딥링크만 보장 |
| 데이터 | 정적 TS 모듈 (`src/data/tactics.ts`) | 서버 없이 출시. 스키마는 추후 CMS/API 이전을 고려해 설계 |
| 전술 보드 | 순수 SVG 컴포넌트 | 의존성 0, 미니/풀 보드 재사용, 추후 애니메이션 확장 용이 |
| 상태 | React state + localStorage | 즐겨찾기 정도의 상태에 전역 스토어 불필요 |

## 6. 화면 설계 (IA)

```
#/            홈 = 라이브러리 (검색바 / 카테고리 칩 / 난이도·즐겨찾기 필터 / 카드 그리드)
#/t/:id       전술 상세 (풀 전술 보드 / 설명 섹션 / 강점·약점 / 카운터 / 연관 전술)
```

- 카드: 미니 전술 보드 프리뷰 + 이름 + 한 줄 요약 + 카테고리·난이도 뱃지 + 즐겨찾기 토글
- 상세: 보드가 첫 화면(above the fold), 설명은 스크롤

## 7. 데이터 스키마 (요약)

```ts
Tactic {
  id, name, nameEn, category(formation|attack|defense|pressing|setpiece),
  difficulty(1~3), summary, description[], strengths[], weaknesses[],
  keyPoints[], counters[](전술 id 참조), famousTeams[], tags[],
  board { players[{x,y,role}], opponents?[], arrows?[{from,to,kind(run|pass|press),curve?}], ball? }
}
```

좌표계: x 0~100(좌→우), y 0~100(자기 골문→상대 골문). 보드 컴포넌트가 실제 SVG 좌표로 변환.

## 9. 리스크

- **콘텐츠가 곧 제품**: 항목 수보다 항목당 품질(정확성·실전성)이 중요. 카테고리당 최소 기준을 정해 유지.
- **보드 표현 한계**: 정적 화살표만으로 복잡한 전환 전술 표현에 한계 → v1.1 애니메이션으로 해소.
- **웹앱 한계**: 홈 화면 설치 유도(PWA)를 v1.1로 앞당길 수 있음.
