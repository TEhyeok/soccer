## 1. 로드맵 원칙

1. **팀 전제**: PM(사용자) + AI 개발자(Claude Code) 2인 페어. 사람 풀타임 개발자 없음 → "구현 난이도"보다 **검증 가능성과 순서**가 우선이다.
2. **기계 검증 게이트**: 트래픽이 없는 단계에서 사용자 행동 지표(체류·설치 수)를 출시 판단에 쓰지 않는다. go/no-go는 **기계 검증 가능한 항목**(테스트 green, Lighthouse, 실기기 QA 체크리스트)만으로 구성하고, 행동 지표는 "계측 가능 상태 도달"까지만 요구한다.
3. **기반은 1회만**: 배포·CI·테스트 하네스는 M0에서 단일 트랙으로 한 번 구축한다. 각 릴리스는 이를 승계·확장할 뿐 재구축하지 않는다.
4. **콘텐츠가 곧 제품**: 콘텐츠 품질 기준·검증 자동화·제작 파이프라인을 기능 개발과 동급 트랙으로 관리한다.
5. **전술 id 불변**: localStorage 즐겨찾기가 전술 id를 참조하므로, 한 번 배포된 전술 id는 절대 변경하지 않는다.
6. **스키마는 additive-only**: 기존 데이터의 재마이그레이션 없이 optional 필드 추가로만 확장한다.
7. **3D는 옵션 모드 · 뷰어 전용 · 지연 로딩**: 3D는 기본 2D 경험을 대체하지 않는다. 별도 청크로 lazy-load하고(기본 번들 불변), 편집은 2D를 유지한다.

## 3. 주요 아키텍처 결정 (ADR 요약)

비판 검토에서 영역 간 충돌로 드러난 사안들. M0에서 ADR 문서로 확정한다.

| # | 결정 | 선택 | 근거 |
|---|---|---|---|
| ADR-001 | **전술 보드 스키마 v2** | **선수 id 도입** (인덱스 기반 기각) | v1.2 편집기의 선수 추가/삭제가 인덱스 안정성을 깨므로 인덱스 기반 애니메이션은 v1.2에서 파산한다. 선수 id는 애니메이션 트위닝·편집기·커스텀 저장·**3D 뷰어** 4개 기능의 공통 기반. 20종일 때 마이그레이션하는 것이 30종·40종일 때보다 압도적으로 싸다 |
| ADR-002 | 애니메이션 데이터 구조 | `Board.steps` optional 확장, 명칭 `steps`로 통일 | 기존 단일 스냅샷 보드 = "1단계짜리 시퀀스"로 자연 해석. 기존 20종 재마이그레이션 불필요. 커스텀 보드 저장 포맷과 3D 뷰어도 동일 스키마 재사용 |
| ADR-003 | 호스팅 | **Cloudflare Pages** | 무료 티어 무제한 대역폭 + PR마다 프리뷰 URL 자동 생성(PM이 코드 안 읽고 눈으로 검증하는 루프의 핵심). 해시 라우팅이라 SPA rewrite 불필요 |
| ADR-004 | 라우팅 | **해시 라우팅 유지** (v1.2까지) | History 전환은 PWA 캐시·필터 직렬화·기존 딥링크와 상호 회귀 폭탄. 검색 유입 실측 데이터가 생긴 후(v1.2 이후) 재평가 |

| ADR-006 | 애널리틱스 | 쿠키리스 경량 도구 (Plausible/GoatCounter 계열) | 무서버 제약 + 프라이버시 고지 최소화. 이벤트 사전(Event Dictionary)은 단일 문서로 관리 |

| ADR-008 | **3D 렌더링 스택** | **three.js WebGPURenderer + WebGL2 자동 폴백**, 별도 청크 lazy-load, 뷰어 전용(편집은 2D 유지) | WebGPU가 Chrome·Firefox·Safari(iOS 26+) 기본 지원 임계점 도달, three.js r171+가 자동 폴백 제공 — 기기 분기 코드 불필요. 네이티브 앱·게임엔진 WASM export(20~50MB)는 2인 팀 규모와 번들 예산에 부적합. 에셋은 CC0(Quaternius 등)+Mixamo만 사용 — 상용 게임 립 에셋은 라이선스 무효로 금지. 실기기 성능 검증은 v1.1 스파이크에서 선행 |
